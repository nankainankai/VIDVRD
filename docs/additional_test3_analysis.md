# 追加三个测试视频：结果与失效分析

可随仓库下载的指标、五视频预测和追加检测/轨迹证据见 [精简结果快照](../experiments/results/performance_validation_20261002/README.md)。原始大型运行目录保留在本地。

新增三个视频完整执行了检测、跟踪、关系识别和导出，未根据它们的 Gold 调整预测配置。接口调用可用，但这组细粒度关系成绩很低：mAP=0、R@50=0，已标注类别关系标签覆盖率 @10=9.52%。连同之前两个测试样例，五视频汇总 mAP=1.33%、R@50=3.45%、标签覆盖率 @10=18.52%。最早两个样例的 50% 标签覆盖率不足以代表更多视频的效果。

## 范围和运行方式

按原固定测试清单顺序，选择第 3–5 个视频：`ILSVRC2015_train_00091004`、`ILSVRC2015_train_00165004`、`ILSVRC2015_train_00234014`。只读取视频元数据选样，预测阶段未读取 Gold 标签。配置为 `configs/benchmark_test.json`，使用 qwen3.8-flash、关闭思考，最终复核为 qwen-vl-max；未启用新的实验候选或提示词策略。

本轮使用本地 Rex-Omni 重新检测，每三帧一个采样锚点，三个视频分别有 122、36、18 个检测锚点。原始运行与选样依据在 `runs/performance_validation_20261002/additional_test3/`。

默认配置评测整个本地 Gold test split（10 个视频），其中未运行的 7 个视频保留为无预测。该完整范围报告保留在 `reports/`；本次预先选定的三个视频另有 `reports/requested/` 报告，三条空预测同样计入请求范围，不按是否成功识别来筛样。新标签报告同时显示完整范围与请求子集，避免混淆分母。

## 检测类别和 Agent 分别出了什么问题

**第三个视频的前端类别不一致。** 检测器产生 10 个原始对象观测，标签先后出现 sheep、cattle、horse、lion，没有 antelope。Gold 的两条对象轨迹均标为 antelope。这是与评测标签的不一致，不是本文对真实动物物种的独立判定。类别随采样帧变化，当前类敏感跟踪最终没有导出轨迹，因此没有对象对供 Agent 判断，语义 API 次数为 0。

可追溯到 `videos/ILSVRC2015_train_00234014/detect/detections.jsonl`、`track/tracks.jsonl`、`track_qc/report.json` 及预测轨迹文件。原图证据保存在 `diagnostics/ILSVRC2015_train_00234014_frame0.jpg`。本轮未把测试 Gold 类别回填到预测，也没有通过降低轨迹过滤门槛来制造正确类别。

**前两个视频主要缺少细粒度关系。** 斑马视频在 Gold 帧上的所有对象检测都被成功匹配，IDSW=0，但模型主要输出 `walk_right`；已标注关系包含 `run_left`、`run_right`、`follow` 等，不能按精确谓词规则获得相同标签命中。狗—蛇视频则漏掉多个动作与空间组合、深度关系和 watch。这些不是接口额度失败。

**轨迹覆盖与区间仍有限制。** 23 条 Gold 中，5 条因没有相应类别轨迹受限，6 条因轨迹覆盖不足受限；仅 12 条在乐观轨迹上界下可能匹配。在这 12 条中，11 条最终缺少正确类别三元组，1 条存在正确三元组却未达到时空匹配条件；实际没有匹配成功的关系。上界忽略预测额外体积等约束，只是诊断，不是已取得召回。

将相同窗口输出做固定 30 帧、取消合并上限、保留长短候选三组离线对照，三组均关闭最后复核，mAP 都为 0，追加 API 调用为 0。对这组三视频，只改合并时间或排序没有修复主要问题。这些方案在追加测试前已经存在，本轮未按新测试分数继续改参数。

## 成本和完成率

三个视频总长约 19.9 秒，完整流水线墙钟耗时 1267 秒，即 21 分 7 秒。实际 API 累计约 82.9 秒，不能把全部耗时归因于千问；其余时间包含本地模型加载、检测和其他处理，不等同于精确测量的纯 GPU 推理时间。

本轮实际发起 8 次请求、8 次尝试，全部成功，未重试，未出现配额、内容检查或认证错误。输入 token 80632、输出 token 5482，总计 86114；账单费用未知。第三个视频没有可用轨迹，所以未调用关系模型，不能描述为“该视频的视觉关系请求成功”。

运行完成率为 3/3，但只有 2/3 视频同时有非空轨迹和关系输出。已在 runtime 报告新增 `output_availability`，区分“流程执行完成”和“产生非空预测”，两者都不等于预测正确。没有导出文件的旧运行标记未知，不按零输出处理。

三组开发真实对照另用了 353775 token、24 次请求；开发优化与此次追加测试合计 439889 token、32 次成功请求，不包含此前模型切换和预检的用量。

## 五视频汇总的含义

汇总使用固定测试清单前五个视频，保存两个来源的预测 SHA256、有效配置哈希和代码指纹。有效配置相同，但前两个视频复用了历史检测，新增三个视频执行新检测；汇总只是五视频预测诊断，不能当作一次统一的完整端到端耗时测试，也不能把不同样本组的成绩差异解释为算法提升。

| 评测范围 | 原始 Gold 关系 | 官方兼容 mAP | R@50 | Tagging P@1 | 已标注标签覆盖率 @10 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 最早两个测试样例 | 6 | 3.33% | 16.67% | 50% | 3/6 = 50% |
| 新增三个固定测试视频 | 23 | 0% | 0% | 0% | 2/21 = 9.52% |
| 五个视频汇总 | 29 | 1.33% | 3.45% | 20% | 5/27 = 18.52% |

五视频产物在 `runs/performance_validation_20261002/combined_test5/`；汇总和离线评测没有新增 API 调用，仍不是完整 200 视频官方测试集。

## 对结项评测的影响

视频级标签建议确实更贴近辅助标注，也允许输出部分轨迹和粗略时间区间；但它仍要求准确类别、谓词与方向，这次扩大样本后分数仍不高。当前问题需要改善类别一致性、双向动作/姿态识别和细粒度谓词判断，不能仅靠放宽时间窗口解决。

固定完整短片段 Presence、人工采纳率和修改耗时仍是适合辅助标注的后续评测。`runs/completion_review_v1/` 已有不依赖 Gold 区间的十片段清单，目前完整人工标注尚未完成，不能报告其精确率、F1 或节时收益。立项书若承诺了具体细粒度检测指标，应同时如实对照该指标。

验证定位：`src/vidvrd_auto/evaluation/runtime.py:11:1` 的 `summarize_run`；`evaluation/tagging.py:8:1` 的 `evaluate_known_label_coverage`；`evaluation/vidvrd.py:196:1` 的 `run_evaluation_suite`。158 项 unittest 通过，包含空输出不算非空预测、无导出文件标记未知、完整 Gold 分母与请求子集分开保留。
