# “Agent 赋能的视频关系理解”大创验收说明

本页把项目申请书中的目标转换为可执行、可核验的工程证据。结论必须来自运行产物；未完成完整数据实验时，不把局部结果写成论文级结论。

## 目标与实现对应

| 申请书目标 | 当前实现 | 验收证据 |
|---|---|---|
| 原始视频到结构化关系的自动闭环 | `ingest -> vocabulary -> detect -> track -> track_qc -> relation -> verify -> export -> evaluate` | `run_manifest.json` 的阶段状态、配置哈希和产物清单 |
| 开放词汇视觉感知 | Rex-Omni 为正式检测器；DINO-X 混合路线作为独立对照配置 | `detect/detections.jsonl`、`configs/experimental_hybrid_dinox.json` |
| 跨帧目标轨迹 | 冻结的 OC-SORT 核心加稀疏调度与短缺口插值 | `track/tracks.jsonl`、`track_qc/report.json` |
| 多模态关系理解 | 轨迹候选路由、双视图故事板、受约束的多模态 Agent 动作 | `semantic/evidence_packets.json`、`semantic/run.log` |
| 规划、反思与一致性校验 | 补帧/候选扩展一次闭环；最终视觉复核动作经过确定性校验后才能应用 | `semantic/agent_audit`、`verify/qc.json` |
| 可视化工具 | `vidvrd-render` 叠加轨迹框、ID、关系箭头和当前三元组 | `visualization/*.mp4` |
| 关系检测标准评测 | VidVRD-helper 协议兼容 mAP、R@50/100、tagging P@K | `official_vidvrd.json/md` |
| 跟踪与关系诊断 | Gold 标注帧 MOTA/MOTP/IDSW、轨迹 IoU、关系 P/R/F1、base/novel 分析 | `diagnostic_track_aligned.json/md` |
| 可复现实验 | 独立离线评测命令，不重跑检测、跟踪或模型 API | `vidvrd-evaluate` 与固定 JSON 产物 |
| 固定开发/测试划分 | 开发集只用于来源分数校准，测试集保持独立 | `experiments/dev_videos.txt`、`experiments/test_videos.txt` |

## 推荐验收流程

1. 环境检查与单元测试：

   ```powershell
   python -m compileall -q src tests
   python -m unittest discover -s tests -v
   ```

2. 端到端运行：

   ```powershell
   vidvrd-auto --videos videos.txt --run-dir runs/acceptance --config configs/acceptance_dachuang.json
   ```

3. 不调用 API 的离线复评：

   ```powershell
   vidvrd-evaluate --pred-relations runs/acceptance/pred/relations.json `
     --pred-trajectories runs/acceptance/pred/trajectories.json `
     --out-dir runs/acceptance/reports --scope gold_split
   ```

4. 生成可视化演示：

   ```powershell
   vidvrd-render --video videos/example.mp4 `
     --relations runs/acceptance/pred/relations.json `
     --trajectories runs/acceptance/pred/trajectories.json `
     --video-id example --output runs/acceptance/visualization/example.mp4
   ```

## 指标解释边界

- `official_vidvrd.json` 中的 mAP 才是关系检测主指标。只跑部分 Gold 视频时，报告同时给出 requested-only 诊断值，不能把它当作完整 benchmark。
- `diagnostic_mot.mota` 只在 VidVRD Gold 有标注框的帧上计算，适合定位漏检、误检和 ID Switch，不冒充全帧 MOTChallenge MOTA。
- 本地 Gold 目前只有 50 个视频，其中 test split 10 个；完整论文结论仍需官方完整测试集或申请书约定的公开数据集。
- 模型分数是排序分而非校准概率；所有报告都保留配置、模型、提示词版本和代码指纹。

## 结题前仍需形成的实验材料

代码已具备统一评测入口，但结题报告仍应补齐实际数据结果：主路线、关闭 Agent 复核、逐帧参照、DINO-X 混合路线至少四组；统一报告运行时间、API 调用量、mAP、R@50/100、Gold-frame MOTA、IDSW 和关系 F1。若无法取得完整 200 个 VidVRD test 视频，必须在表题中写明“10-video protocol-compatible subset”。

来源系数当前是可配置工程初值，必须只在 `experiments/dev_videos.txt` 上选择；确定后冻结配置，再对 `experiments/test_videos.txt` 运行一次。禁止根据单个视频或测试集结果反向调参。
