# 第一阶段：人工标注与半自动流程构建

## 目标
- 做出 50 条 Gold：轨迹用“关键帧标注→插值/传播→少量修正”得到逐帧框；关系按时间段标注（start~end），不是逐帧点。
- 跑通半自动：对同一批视频自动生成关系候选（1fps抽帧、画框+ID/颜色提示、按3个关系一组询问、VggSound音频先验、耦合补全如left/right），并导出为与 Gold 一致的 JSON。
- 建立可复现评测：一键输出 Presence P/R/F1、产出率、失败案例清单，用于持续改代码直到满意。

## 分工
- 标注组（2人）：完成 50 条 Gold（轨迹+关系），同步沉淀 1 页标注规则/易错点（谓词边界、起止帧口径、耦合补全规则等）。
- 工程组（2人）：整合 VIDVRD 的窗口化/可视化骨架与半自动关系候选生成；修复LLM输出/解析一致性；把半自动 triplets 转为统一关系JSON（先整段覆盖或窗口覆盖）；每天用50条跑评测并迭代。

## 交付物
- `gold/trajectories_gold.json`、`gold/relations_gold.json`（50条）
- `pred/relations_pred.json`（schema 对齐 Gold）
- `tools/evaluate_presence.py`（一键评测）
- `report.md`（指标表+失败案例+原因分类等等）

# 第二阶段：全自动标注（openclaw skill）

## 目标
- 给定一组视频，一键产出可用的“轨迹 + 关系”标注结果，并且可复现（同一参数同一输出）。
- 流程节点化：每一步都有明确输入/输出，支持缓存与断点续跑，失败可定位到具体环节。
- 质量可控：先用便宜规则/轻量模型兜底，高风险片段再触发更强模型做复核或补全。

## 流程（节点化）
- 读入视频（本地或URL）→ 抽帧 → 目标检测（出框）→ 多目标追踪（连成轨迹）→ 片段切窗 → 关系候选（规则 + 大模型）→ 跨窗聚合 → 质检 → 导出。

## 分工
## 成员1（流程串起来）
- 负责 openclaw skill 的整体编排与入口：给一组视频，一键跑完全流程。
- 负责“数据落盘与复现”：所有中间结果按统一命名保存；关键参数随运行记录，便于复跑与对比。
- 负责缓存与成本控制：同一视频同一参数不重复调用大模型；能从任意中间结果继续跑。

## 成员2（让框和轨迹稳定）
- 负责抽帧策略与目标检测接口：先确保能稳定出框，再逐步优化召回/速度/成本。
- 负责多目标追踪与轨迹整理：把逐帧框连成 track（含 `track_id`、类别、逐帧bbox）。
- 负责轨迹质检与触发条件：断裂/漂移/覆盖率异常时标红，作为后续复核入口。

## 成员3（产出关系）
- 负责规则关系兜底：基于几何与时序，产出最小可用的位置类关系与耦合补全（例如互为左右/上下）。
- 负责大模型关系候选：对短片段（窗口）生成关系候选，并返回带起止帧的结构化结果，便于后续聚合。
- 负责输出口径统一：关系结果必须能无损映射到最终 schema（主体/客体/谓词/起止帧/置信度或来源）。

## 成员4（结果合并验收）
- 负责跨窗口聚合：把窗口级关系合并成更长的事件段，减少碎片化与重复。
- 负责冲突检测与补全：互斥关系、重复关系、缺失关系的处理规则；必要时触发复核。
- 负责验收与报告：输出产出率、失败类型分布、典型失败样例，用于驱动下一轮迭代。

## 产出
- 每个视频至少产出 3 类结果：轨迹（逐帧track）、关系（带起止帧事件段）、质检报告（产出率/异常点/失败原因）。
- 全部结果遵循同一套 schema 与命名口径，保证第一阶段 Gold 与第二阶段自动结果能直接对齐评测。
