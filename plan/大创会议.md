## 半自动标注方案

### 轨迹标注

采用标注模型进行标注，目前最优的模型是DINOV3，但是价格较高，采用本地大模型  **Rex-Omni**  进行标注。

但是标注一个视频时间成本较高，所以先对每个视频的第一帧进行标注，确保这个视频有两个或以上有意义的物体（没有选择关键帧标注的原因是数据集中视频较多，支持大规模放弃）。

筛选出2个或2个以上物体的视频进行全部帧全部类别标注。

### 关系标注

我们采用调用大模型 API 的形式进行标注视频关系类别。

考虑到视频输入进大模型会自动抽帧处理，而且让大模型自己抽帧会耗费较长时间，而视频关系检测需要精确给出关系存在的duration，
关系标注考虑到效率成本和准确率，我们的方案是按照一秒一帧的形式输入到大模型，
不让大模型考虑关系存在的duration，后续通过截取视频的方式让得到的关系覆盖整个视频。

同时我们标注的数据集Vggsound在标签中存在一些关系（bark at、sing ......），在输入进大模型时通过prompt提示这个视频中存在音频关系，提升大模型生成关系的准确率。

考虑到关系类别数量较多，全部一次输入大模型容易忽略其中的一些类别，所以我们按照3个关系为一组进行输入，询问关系是否在视频中存在。

后续通过可视化的脚本筛选关系：

<img src="大创会议.assets\image-20260401214113511.png" alt="image-20260401214113511" style="zoom:80%;" />

将筛选的关系进行耦合补全：
A-left-B ---> B-right-A





## 自动化标注方案

目标：设计 openclaw 的 skill 实现全自动关系标注。

预计方案：

1. 自动从网络下载视频数据
2. 关键帧出框 + 大模型粗筛：调用脚本，视频进行关键帧提取；调用标注模型，对每个关键帧标注物体框；调用大模型，检查关键帧的标注，并且选择是放弃该视频，还是通过裁剪视频得到高质量视频片段。
3. 逐帧标注 + 轨迹追踪：调用标注模型，逐帧进行物体框标注；调用轨迹追踪模型，将每帧的标注连接成物体的轨迹。
4. 大模型筛选：抽取目前标注视频的部分帧，调用大模型判断 “是否为同一个物体” 或 “轨迹框是否偏移严重” 或 “轨迹类别是否正确”

**考虑成本及效率，可能可以选择利用高性能标注模型（如 DINO）对关键帧进行标注，其他的通过较小模型进行追踪或生成。**

5. 关系标注规则制定：标注严格的关系标注规则，可以根据现有的标注 或 常识进行指定，如 左右等位置关系 的定义、sing with | sing to的区别定义、主语和谓词的耦合关系 ...... 并且将所有的关系类别进行细粒度划分，如通过 是否接触 等将所有关系类别分层，或设计 通过 iou、相对位移速度 等信息判断关系的策略。
6. 片段关系分类：将一个视频划分为多个30帧的片段（[0, 30], [15, 45] ......），调用 关系检测模型 或 大模型 对每个片段进行关系检测，在关系检测时利用 5 中得到的 关系划分、规则 分别输入。
7. 全局关系分类：调用脚本将从多个片段上得到的关系类别进行统筹，调用 模型 查看整个视频的抽帧以及片段上的关系类别，进一步检测动态关系类别 如 toward等。
8. 检查与补全：调用模型检查得到的关系类别是否冲突或是否存在，如果关系类别存在问题，可以用更强的模型进行进一步检查和筛选，最后通过谓词之间的耦合进行补全，如A-left-B ---> B-right-A
